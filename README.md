# CampusPilot · 杭电校园助手

基于 HarmonyOS、ArkTS 和 ArkUI 的校园助手项目，面向手机和平板，提供对话式入口、课程资料检索和多个校园生活功能页面。当前已接入多模型 API 配置、流式对话、可管理的工作区、原位表单、任务面板联动、系统日程与定时任务、本地历史及全局字号设置，业务服务继续通过适配器联调。

本说明对应截至 **2026 年 10 月 28 日** 的工作区代码。按日期记录的开发内容见 [开发日志](CHANGELOG.md)，模块接口及数据约定见 [联调说明](entry/src/main/ets/INTEGRATION.md)。

## 系统日程、提醒与备忘录

所有工作区都可以通过对话调用系统工具，例如“查看我今天的日程”“明天下午三点安排一小时复习，提前十分钟提醒”“每周一到周五七点半叫我起床”“25分钟后提醒我休息”“把出行清单保存成备忘录”。模型服务需要支持标准工具调用；实际写入前会显示标题、日期和内容，核对后执行。

最左侧 **定时任务 → 日历 / 提醒 / 备忘录** 打开时自动读取数据，可查看设备时间、今天起未来31天日历、管理本应用提醒和本地备忘录，也可直接填写内容创建，不依赖模型服务。“提醒”同时显示本应用代理提醒和有提醒时间的日历日程（包括准时提醒）；“Agent任务”仅显示到期执行模型工作的任务。首次使用日历会请求读写权限；代理提醒会检查通知授权。没有权限或系统能力失败时不会假装成功。

- 日历访问使用 `Calendar Kit`，可见范围由系统授权决定，不保证包含其他应用的私有日历。查询按事件实例展示重复安排；为避免误改整个系列，重复日程修改/删除需在系统日历处理。
- 闹钟使用 `reminderAgentManager` 系统代理服务，退出应用后由系统接管；它属于本应用，**不是系统时钟应用里的闹钟**。部分手机、平板需要开通代理提醒权益；此时会返回失败，可以另行确认改用系统日历提醒。实际响铃仍需检查通知、静音和勿扰设置。
- `1700002` 不一定是已有提醒太多：未获得代理提醒权益时，普通应用的额度也可能为0。本应用提醒为空不能证明是其他应用占满。需要在 AppGallery Connect 申请并启用代理提醒能力，获批后重新生成 Profile 并使用对应签名；单纯声明权限或开启通知不能替代能力资格。日历替代方案创建后在“日历”和“提醒”查看，不会变成系统时钟闹钟。
- 本地备忘录保存于应用沙箱 `local_memos.json`，原子写入并保留备份，最多100条。系统备忘录私有笔记不在本应用读取范围内；“系统分享”由用户选择可接收文本的应用并完成保存。当前模拟器不包含系统备忘录和时钟应用。

## Agent定时任务与统一资料库

- **定时任务 → Agent任务**：保存标题、具体要求、首次时间和执行周期；也可以在对话中说“每天早上9点整理我的日历”。Agent调用 `manage_agent_task`，核对后保存。支持单次、每天、每周和至少15分钟的间隔任务；立即运行不会消耗原定的下一次安排，暂停任务不会被编辑或手动运行意外启用。
- 打开应用时每15秒检查到期任务；错过多次的周期合并为一次，不补跑全部积压。后台申请持久化 `WorkSchedulerExtensionAbility` 调度，由系统根据网络、活跃程度及资源条件择机执行，**不保证后台准点**。任务运行最长85秒，保留最近5次真实结果和失败/中断状态；跨进程原子认领避免前台与后台重复执行。后台不弹授权窗口，日历未授权会返回失败。
- 自动任务仅提供读取时间、授权日历、提醒和本地备忘录的工具，同时按任务要求检索已启用的本地资料。自动任务不能写日历、修改备忘录、发送消息或触发新的定时任务；需要这些操作时回到普通对话核对执行。
- **资料库**：对话导入的附件自动保留独立副本，旧会话文件会尝试迁入；新建文本可粘贴上下文。文字按800字符、120字符重叠分段，可预览、停用检索、加入上下文或复制为对话附件。图片可预览并加入对话；补充图片描述后，描述会参与向量检索，同时保留原图与媒体元数据。
- **RAG 工作台**：资料页使用列表与详情分栏。知识库页可创建多个知识库，选择内置/本地资料范围、在线 Embedding 配置和在线或本地重排序；在线索引按当前切块参数批量构建并持久保存。
- 数据可视化页支持关系图、节点和表格三种视图，可对当前知识库做实际混合检索，命中来源高亮；点击节点可查看片段并加入当前对话。模型与API页管理 Embedding/Rerank 配置；本地算法页可调整关键词/向量权重、BM25、Top K、阈值、上下文预算、本地重排及切块参数。
- 支持导入包含 `revision/chunks` 的RAG索引JSON，保留合法的 `vector/vectorModel`；JSON文件最多2MB，单份索引最多500个片段，单片段最多12000字符。外部只读RAG源可停用；本地资料删除不会破坏已加入对话的附件或引用副本，删除记录阻止旧会话迁移时将其复活。
- API设置保存到设备私有首选项供前后台任务使用，不写回源码。真实 `local_api.json` 仍受Git忽略保护。

## 开发环境

- DevEco Studio：当前已验证版本为 **6.0.2.670**。
- HarmonyOS SDK：项目目标与兼容版本均为 **6.0.2（API 22）**，以 `build-profile.json5` 为准。

## 获取与运行

```powershell
git clone https://github.com/sugary-men/huawei-project.git
cd huawei-project
```

使用 DevEco Studio 打开项目根目录，完成 SDK、依赖同步，并在 Device Manager 中启动设备。连接真机时按本机环境配置调试与签名；当前仓库未提供个人签名材料。

在项目根目录运行：

```powershell
devecocli device list
devecocli build
devecocli run --module entry
```

连接多个设备时指定设备名称或序列号：

```powershell
devecocli run --module entry --device "MatePad Pro 11"
```

本机命令不在 PATH 时的调用示例：

```powershell
& "$env:APPDATA\npm\devecocli.cmd" build
& "$env:APPDATA\npm\devecocli.cmd" run --module entry --device "MatePad Pro 11"
```

当前 DevEco Studio 6.0.2 环境可使用 CLI 构建、部署及 UI 检查；CLI 的 `emulator list/start` 命令要求 Studio 6.1.0 及以上，因此本环境通过 Studio 启动模拟器，再使用 `device list` 检查连接。

## 配置模型 API

### 方式一：应用内填写

点击首页或聊天输入框内、麦克风右侧的模型名称，可切换已保存配置；选择“管理模型 API…”打开独立配置窗口。多组配置可按名称或模型搜索，列表限高滚动，长名称自动省略；没有配置时显示“配置模型”，点击直接进入配置。配置窗口、占位提示和选择列表均跟随全局字号。支持最多20组，可新增、编辑、另存为新配置或删除，每组填写：

- **配置名称**：可选的显示名称，便于区分同名模型的不同服务或账号。
- **服务地址**：服务商提供的 Chat Completions 兼容根地址，例如 `https://api.example.com/v1`。
- **模型名称**：该服务实际支持的模型 ID。
- **API Key**：对应密钥；无鉴权的本地服务可以留空。

应用会拼接 `/chat/completions`，请勿将示例地址当作可用服务。“仅保存”保留当前模型，“保存并使用”立即选中该配置；删除当前配置会切换到剩余配置，删除最后一组后停止使用模型。配置和当前选择保存在设备应用私有首选项，重启保留；普通对话和后台定时任务在下次请求时使用所选模型，已开始的请求保持原配置。

### 方式二：本地文件自动载入

在项目根目录执行：

```powershell
Copy-Item entry/src/main/resources/rawfile/local_api.example.json entry/src/main/resources/rawfile/local_api.json
```

如果已经存在 `local_api.json`，直接编辑原文件，避免覆盖已有配置。内容示例：

```json
{
  "baseUrl": "https://api.example.com/v1",
  "model": "your-model-name",
  "apiKey": "your-api-key"
}
```

重新构建部署后，首次初始化会将原有单组配置或该文件内容迁为默认配置；已有多配置存档时，以应用内配置为准。删除所有配置后不会从文件自动恢复，后续可在应用内新增。`local_api.json` 已被 `.gitignore` 忽略；提交前可检查：

```powershell
git check-ignore entry/src/main/resources/rawfile/local_api.json
```

示例文件只放占位值。**rawfile 配置会进入构建的 HAP 安装包**，Git 忽略并不能隐藏安装包中的密钥；公开分发应由后端保管密钥并代理请求。

模型请求需要设备或模拟器能够访问服务地址。电脑能访问服务不代表模拟器网络已连通；图片分析还需要所选服务和模型支持视觉输入。

## 使用说明

1. 点击左上角 CampusPilot 图标返回首页，显示按时段变化的欢迎语和“今天准备做些什么”；点击工作区名称，进入“准备在某工作区里做些什么”的专属欢迎页。配置 API 后可直接输入或点击快捷提问，回答会逐段显示。
2. 点击“＋上下文”，在独立弹窗中检索资料、加入当前会话，点击“完成”返回对话。
3. 输入框“＋”用于导入文件或选择图片；麦克风按钮用于识别语音，再次点击结束识别。
4. 每次启动先进入首页，不自动打开上次会话；每个工作区以文件夹形式收纳自己的会话，“最近对话”同时按最近消息时间倒序汇总非回收站会话。两处操作的是同一份记录；打开会话不会刷新其时间，选中某一会话后，右侧才出现三点菜单，可将会话移入回收站。
5. 左栏采用固定顶部入口、下方统一滚动的布局。工作区文件夹独立展开/收起，默认展示最近 3 条，支持显示较早会话；最近对话默认显示 8 条，可展开全部。顶部搜索同时筛选两处列表。文件夹、分组和整栏的展开状态会保留到下次启动。
6. 选中工作区后，从右侧“⋯ → 新建对话”创建该工作区的会话；顶部“对话”选中后，通过“⋯ → 新建对话”沿用当前工作区。收起整栏后也先选中对话图标，再从“⋯”新建。仅打开历史对话不会强制展开已收好的工作区。
7. 可以直接说“把计划放到右侧任务面板”“保存为产物”或“切换到学习助手”。Agent 通过模型的工具调用更新界面；所用服务需支持 Chat Completions 的 `tools/tool_calls`。
8. 点击“工作区”标题后，从右侧“⋯ → 新建工作区”创建分区并填写说明、Agent 提示词；选中各分区后，其“⋯”提供新建对话、删除工作区，智能助理和回收站始终保留。删除分区会将其全部会话连同附件移入回收站；恢复到原分区，原分区已删除则恢复到智能助理。仅“永久删除”会清理会话及不再使用的附件副本。
9. 智能助理会按主要需求调用工具归入已有合适分区，不自行创建；无法明确匹配时留在智能助理。此能力需模型支持工具调用。
10. 拖动左右侧栏与正文之间的细长手柄可调整宽度，双击手柄恢复默认。普通调宽保持最小可读宽度；将左侧分隔条向左、右侧分隔条向右拖至本次拖动前宽度的1/3或更小时，松手自动收起；点击侧栏展开按钮或任务面板按钮可恢复拖动前宽度。最小宽度随大字号增加，两侧展开状态及宽度保存在本机。按钮和可点击区域提供按压/悬停反馈，输入框聚焦有边框光效。侧栏展开/收起使用220毫秒原生逐帧布局，拖动时直接跟手；对话气泡与输入框采用原生宽度约束同步排版，过渡内容在各自区域内裁切。
11. 回复中的明确清单可直接勾选；正文和表格里的 `___`、`＿` 可原位填写，`□` 选项可勾选，“是否 / 单选”字段互斥，“多选”字段可同时选择，无须先打开编辑模式。点击“填写 / 补充”还可修改普通表格或补充要求；“确认内容”立即让 Agent 检查当前填写和勾选并回复，空表也可提交检查缺失项，之后可“再次检查”。“产物与记忆”也使用相同交互，产物详情可点击“带上反馈继续”。填写会本地保存，确认检查不等于外部表单提交或现实任务完成。
12. 右侧任务可以手动勾选完成；“让 Agent 继续”和“推进下一步”会结合当前面板发起真实对话，不会自动把待办标成已完成。点击产物可查看 Markdown 正文并复制。

### 填写、选择和显示设置

回复正文、产物详情和任务记忆使用同一套交互：横线直接填写，清单和选项直接点击；普通表格通过“填写 / 补充”修改。“确认内容”会保存并立即发送检查请求，携带原文、当前字段值、空字段、未选项和补充说明；Agent判断缺失或矛盾并给出下一步，信息完整时依据实际填写返回结果。再次点击可重新检查，保留聊天输入草稿和待发附件。“带上反馈继续”、普通追问和“推进下一步”也会将这些值一起交给 Agent。切换会话和重启后仍保留；生成内容改版后需核对并重新确认。

可让 Agent 按以下 Markdown 模板生成表单；“是否 / 单选”为互斥选项，“多选”可同时选择：

```markdown
| 项目 | 请填写 |
| --- | --- |
| 出行日期 | ___（例：2026-11-01） |
| 同行人数 | ___ 人 |
| 是否出行 | □ 是 □ 否 |
| 装备（多选） | □ 水 □ 伞 |

- [ ] 已核对票据
实付＿元。
```

左下角“设置”可调整全局字号（80%–130%，默认90%），对话、表单和界面同步更新；气泡按钮与留白、左右侧栏卡片、搜索框、聊天输入区、表格列宽及填写框的尺寸与间距一起缩放，提示文字也遵循同一设置，重启后保留。Agent气泡在当前对话区居中，默认字号下最大宽度720vp，随字号缩放；空间较窄时自动填满可用宽度并保留两侧留白，侧栏收起后仍居中，正文保持左对齐。用户气泡按内容收缩并右对齐，默认字号下最大648vp，长文本自动换行。输入框在对话区居中，上方为多行文字，下方左侧为附件/麦克风，右侧为发送/停止；输入框默认与Agent气泡等宽，空内容和短内容也保持该宽度，并随侧栏和字号调整。多行输入自动增高，默认字号下输入区域最高144vp，超出后内部滚动，回车换行、点击发送提交。普通说明列表保持原来的排版，不再统一加上勾选框。

回答底部提供朗读/停止和复制图标；复制保留正式回答的Markdown正文，并显示成功反馈。提问与回答分别记录发送/完成时间，显示在气泡右下角：当天显示“10:00”，本周显示“星期四10:00”，今年显示“9月3日10:00”，跨年显示“2020年3月2日10:00”。日期标签按设备本地时间更新，重新打开沿用原始消息时间；旧记录没有独立时间时显示“时间未记录”。

工作区预设集中在 [`WorkspaceConfig.ets`](entry/src/main/ets/config/WorkspaceConfig.ets)，每个工作区分别配置角色、系统提示词、开场白、快捷提问和初始任务模板。通过 Agent 切换工作区时，当前对话、目标、摘要和产物保留，任务模板更换；手动点击侧栏工作区进入对应欢迎页，历史记录从其会话列表或最近对话打开。仅浏览欢迎页不创建空白会话，发送第一条消息才建立本地会话；输入框中的附件和已选上下文会一起进入该会话。

支持文本型 TXT、MD、CSV、JSON、LOG、PDF、DOCX 文件；扫描 PDF 暂无 OCR，可改为图片输入。每条消息最多 4 个附件，单个原文件上限 12 MB；更详细的文本、图片预算见 [联调说明](entry/src/main/ets/INTEGRATION.md)。

历史记录位于设备应用沙箱的 `filesDir/chat_sessions.json`，附件副本位于 `filesDir/chat_attachments/`，不会写到项目目录。应用每次启动先显示首页欢迎页，历史会话从侧栏打开；卸载或清除应用数据会清除这些记录。当前采用本地 JSON 与备份文件，尚未额外加密，也未实现跨设备同步。

以下是当前开发机的 PowerShell 示例，其他环境需修改 DevEco Studio 安装路径：

```powershell
$devEcoRoot = 'F:\DevEco Studio'
$nodeExe = Join-Path $devEcoRoot 'tools\node\node.exe'
$typescriptModule = Join-Path $devEcoRoot 'tools\ohpm\node_modules\typescript\lib\typescript.js'

foreach ($test in (Get-ChildItem tests -Filter '*.test.cjs')) {
    & $nodeExe $test.FullName $typescriptModule

}
```
